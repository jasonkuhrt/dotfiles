# N-up

An n-up presents options for one design question side by
side, round after round, until Jason says final. Use the
context and content that make the choice clear.

## Options

- Use `show-me` to present options as Jason would encounter
  them. Use a faithful view of the real target when it is
  practical and authorized, with a mockup as the fallback.
  Render in the conversation when the host supports it.
- Label options A, B, C… within each round. Messages carry
  the round number, so a label never encodes its round. A
  caption, if present, describes the option without
  repeating its label.
- A named count sets the first round. A 6-up opens with six
  options. When Jason leaves the count open, show the
  distinct options the design question warrants.
- When options vary only in an amount, offer a slider where
  supported and include its value in the response. A slider
  can take the place of those options when Jason leaves the
  round's count open. When options have separable parts,
  let him combine them in the widget where supported or
  name the combination in his reply.

- Bad: after Jason asks for three close variations, the
  next round gives him only a size slider.
- Good: it shows three close variations and offers a slider
  for the size he wants to tune.

## Controls

When the host supports a widget that sends to chat, give
each option a button with its short label. Continue lets
Jason keep, lower or raise the count and set a spread from
polish to diverge. Final submits the pick with "final" and
any note. Count and spread apply only to Continue. The note
field can send with a pick or on its own.

If picking and selecting Final are separate controls,
either order works. Selecting Final after a pick was sent
submits that same subject, round and pick with "final".

When several subjects are open and the host supports a
shared widget, give each subject its own tab and controls.
On other hosts, label each subject and round so Jason can
answer them independently.

A widget submission identifies the subject, round and
option when there is a pick. A typed label works when the
subject and round are clear. Typed replies can specify the
same count, spread, values, combinations, notes and final
choice.

- Bad: Jason clicks D in blockquotes round 5 and then
  selects Final, but the chat receives only his first pick.
- Good: selecting Final also sends "Blockquotes round 5: D
  final".

## Rounds

A pick without "final" starts the next round. Use the count
and spread Jason gives and incorporate his note. With no new
count, keep the current count when showing options. With no
spread, show variations on the pick. If he asks to inspect
or correct a design instead, answer that request and keep
the n-up open. Only his "final" ends the series. A final
submission naming an earlier pick ends the series on that
pick.

A pick permits applying it only if the task does. When a
pick is applied for a live look, the reply that applies it
also shows the next round; it does not report the series
as done.

After final, complete and verify any implementation the
task calls for. If the choice is already applied, confirm
that rather than building it again.

- Bad: callout A is applied and reported as finished.
- Good: callout A is applied for a live look, and the
  same reply shows the next round on it.

## History

Keep a durable file for each series. As each round is shown
and answered, record its options or durable rendering
locations, and any controls, note and pick Jason supplied.
Keep the file's location in the session record. Use the
file when Jason returns to an earlier round.
